# Инструмент визуализации графа зависимостей (Вариант №9)

## 1. Общее описание
CLI-приложение на языке Python для анализа и визуализации графа зависимостей
пакетов формата **Alpine Linux (`apk`)**. Инструмент разработан без
использования сторонних библиотек и готовых менеджеров пакетов: загрузка
индекса `APKINDEX.tar.gz`, разбор метаданных, обход графа зависимостей и
экспорт изображения реализованы средствами стандартной библиотеки Python.

### Реализованные этапы работы
1. **Этап 1 (Конфигурация):** разбор и валидация параметров командной строки.
2. **Этап 2 (Сбор данных):** загрузка и распаковка `APKINDEX.tar.gz` по URL,
   извлечение прямых зависимостей заданной версии пакета.
3. **Этап 3 (Построение графа):** транзитивный обход зависимостей
   алгоритмом **BFS без рекурсии** (`collections.deque`), обработка
   циклических зависимостей и поддержка тестового репозитория (`--test-mode`).
4. **Этап 4 (Порядок загрузки):** вычисление порядка установки пакетов
   (зависимости загружаются раньше целевого пакета).
5. **Этап 5 (Визуализация):** генерация текстового описания графа на языке
   **PlantUML** и сохранение диаграммы в формате **SVG**.

---

## 2. Функции и настройки (параметры CLI)

| Параметр | Обязательный | Описание |
| :--- | :---: | :--- |
| `--package` | Да | Имя анализируемого пакета (например, `curl`, `zlib` или `A` в тестовом режиме). |
| `--repo` | Да | URL-адрес зеркала репозитория Alpine Linux или путь к файлу тестового графа. |
| `--version` | Да | Версия анализируемого пакета (например, `8.9.1-r0`). |
| `--test-mode` | Нет | Флаг включения режима работы с локальным тестовым файлом репозитория. |
| `--output` | Нет | Имя выходного файла с изображением графа в формате SVG (по умолчанию `graph.svg`). |
| `--load-order` | Нет | Флаг вывода порядка загрузки зависимостей вместо списка смежности графа. |

## 3. Команды запуска и тестирования

### Запуск модульных тестов
Для проверки всех модулей (CLI, парсер, BFS, порядок загрузки, PlantUML):
```bat
python -m unittest discover -s tests
```

### Примеры запуска на Windows (`run.bat`)

#### 1. Тестовый режим (граф с транзитивностью и циклом `B <-> C`)
```bat
run.bat --package A --repo tests\sample_repo.txt --test-mode --version 1.0 --output test_graph.svg
```
Вывод порядка загрузки в тестовом режиме:
```bat
run.bat --package A --repo tests\sample_repo.txt --test-mode --version 1.0 --load-order
```

#### 2. Демонстрация визуализации для трех различных пакетов Alpine Linux
Пакет **zlib** (базовая библиотека сжатия):
```bat
run.bat --package zlib --repo https://alpinelinux.org --version 1.2.13-r1 --output zlib.svg
```

Пакет **curl** (сетевая утилита с транзитивными библиотеками):
```bat
run.bat --package curl --repo https://alpinelinux.org --version 8.9.1-r0 --output curl.svg
```

Пакет **git** (разветвленное дерево зависимостей):
```bat
run.bat --package git --repo https://alpinelinux.org --version 2.40.1-r0 --output git.svg
```

## 4. Сравнение со штатными инструментами Alpine Linux (`apk`)
При сравнении результатов работы утилиты со штатным пакетным менеджером
(`apk add --simulate <пакет>` и `apk dot <пакет>`) наблюдаются следующие
особенности и расхождения:

1. **Виртуальные зависимости (`so:`, `cmd:`, `pc:`):** в файле `APKINDEX`
   зависимости часто указываются через разделяемые библиотеки (например,
   `so:libc.musl-x86_64.so.1`) или команды (`cmd:sh`). Штатный `apk` сопоставляет
   их по полю `P:` и `p:` (provides), тогда как данная утилита очищает
   префиксы и связывает имена напрямую по каталогу пакетов.
2. **Выбор провайдеров и версий:** при наличии нескольких пакетов,
   предоставляющих одну и ту же библиотеку, реальный `apk` учитывает приоритеты
   репозиториев и установленные пакеты системы, тогда как статический
   анализатор берет первое совпадение из индекса.
3. **Порядок загрузки:** в штатном `apk` порядок установки внутри одного
   уровня зависимостей может сортироваться по алфавиту или размеру пакета,
   тогда как в текущей реализации порядок определяется очередностью обхода
   ребер в графе.
